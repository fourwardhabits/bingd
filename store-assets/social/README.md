# bingd. social asset kit

Everything here is generated by [`render.mjs`](./render.mjs). Change the script,
re-run it, commit the outputs. Nothing in this folder is hand-edited, and nothing
in it is loaded by the app.

```
node store-assets/social/render.mjs
```

**Avatar**

`profile-mark-1024.png`

Build your ranked list, compare taste with friends, find your next binge together.

The handle appears in no graphic. It changes if `@bingdwatch` is taken, and a
handle burned into an avatar is a file you have to re-cut when that happens.

`profile-lockup.svg` sets `bingd.` as a `<text>` element, so it renders correctly
only where DM Serif Display is installed. The PNG is the master. `profile-mark.svg`
is pure geometry and renders anywhere.

No user counts, no testimonials, no ranking claims. Nothing is asserted that the
product does not do.

The positioning line is set on one line or not at all. `render.mjs` picks the
largest size that still fits the canvas width and drops the line entirely below
30px rather than breaking it, so a narrower asset loses the line instead of
gaining an awkward wrap.

## Three rules these files keep

**No third-party artwork.** No posters, no key art, no studio marks. Every pixel
is brand-owned. Screenshot posts are a separate job and carry a separate artwork
question.

**No ring, no outline, no handle** on either profile master. Paper runs to all
four edges.

**The avatar is the mark, not the wordmark.** `bingd.` set small enough to fit a
32pt avatar is illegible, and the mark already reads at that size. The app icon
is the same drawing at inset 0.78, which suits iOS's superellipse and not the
circle every social platform crops to; both profile masters are sized so their
content sits well inside the inscribed disc, with the mark's half-diagonal at 346
against a 512 radius.
